## 设备：“打开它。里面有什么，谁依赖它？”

**可以看到**：每台设备的状态、故障和 LED。走到机柜前，打开一台服务器，把它**拆解**到部件（PSU、风扇、内存条、硬盘、GPU）；数据源提供时，还会显示每个部件的数值。

**假设推演**：某个部件故障时，会列出所在设备、其上运行的业务（`runs` 列）和租户。12 个月内到期的维保会在导入时标出。

**数据来源**：Devices 工作表（rack, u, model, name, role, height_u, power_cords, serial, owner, warranty_end, runs）。型号文本会与设备库进行匹配（依次为精确匹配、别名、型号代码，最后是模糊匹配：“PE R740XD”也能找到正确的服务器）。未知型号显示为待识别的普通方块。

**设备库**：服务器、GPU 节点、交换机、存储、PDU、UPS、制冷单元和冷却液分配单元（CDU），包含尺寸、重量、功耗、气流、冷却方式和部件树，基于公开的规格书和手册构建，并以一个开源设备类型库作为初始数据。性能字段（核数与 TDP、GPU 吞吐、存储 IOPS、网络带宽）正在补充中，以便设计模式据此进行选型配置。

## Token：“哪台服务器产出的 token 最多，耗电代价多大？”

**可以看到**：GPU 节点上的每秒 token 数柱状图，整个机房以颜色表示的每千瓦时 token 数，监控模式中的 token 产出排行，以及报告模式中按业务、租户、模型和服务器统计的 token。

**指标**：每千瓦时 token 数 = 产出的 token 数 ÷ 服务器（或机柜，含其分摊的设施能耗）消耗的电能。它是把 AI 机房的产出和电费联系起来的那个数字，可以按服务器、按机柜、按租户计算。当能耗一侧是模型估算而非计量值时，会标注为**估算**。

**假设推演**：每个场景都会报告 **token 损失**。让一路供电故障、停掉一台制冷单元、制造一处漏液，Token 图层就会显示随之消失的服务能力。

**目前的数据**：演示机房自带 token 计数器，您也可以通过 Readings 工作表导入 token 和功率历史数据。来自推理服务栈指标和 GPU 遥测的**实时数据**通过代理程序的采集器接入；采集器已开发完成，但尚未在真实运行的系统上测试（路线图）。

在大多数 AI 机房里，每千瓦时 token 数仍然是一个靠电子表格算的指标：功率看一个仪表盘，token 看另一个。把两者放到同一个机柜上，两台服务器、两个机柜或两个租户之间的对比，看颜色就行。试试[每千瓦时 token 数计算器](/resources/calculators/tokens-per-kwh/)，或阅读[每千瓦时 token 数：AI 机房最关键的那一个指标](/resources/guides/tokens-per-kwh/)。

## 成本分摊与容量

报告模式并列给出按业务、租户、模型和服务器统计的 token，按您的电价计算的能耗和成本，以及每千瓦时 token 数，因此成本分摊是一份报告，而不是一张电子表格。估算值均有标注。
