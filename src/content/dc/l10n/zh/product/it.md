## 设备（Device）：“内部有哪些部件，哪些业务依赖它？”

**呈现内容**：每台设备的状态、故障与 LED。走到机柜前打开服务器，将其**拆解**至部件（PSU、风扇、内存条、硬盘、GPU）；数据源提供时，同时显示各部件的数值。

**故障推演**：部件故障时，列出所在设备、其承载的业务（`runs` 列）与租户。12 个月内到期的维保在导入时予以标出。

**数据来源**：Devices 工作表（设备表：rack, u, model, name, role, height_u, power_cords, serial, owner, warranty_end, runs）。型号文本与设备库依次进行精确匹配、别名匹配、型号代码匹配和模糊匹配（例如“PE R740XD”可匹配到正确的服务器）。未知型号显示为待识别的通用方块。

**设备库**：涵盖服务器、GPU 节点、交换机、存储、PDU、UPS、制冷单元与 CDU（冷量分配单元），包含尺寸、重量、功耗、气流、冷却方式与部件树，依据公开规格书和手册构建，初始数据来自一个开源设备类型库。性能字段（核数与 TDP、GPU 吞吐、存储 IOPS、网络带宽）正在补充，以支持设计模式据此进行选型。

## Token：“哪台服务器 token 产出最高，能耗代价多大？”

**呈现内容**：GPU 节点上的每秒 token 数柱状图，全机房以颜色表示的每千瓦时 token 数，监控模式（Monitor）中的 token 产出排行，以及报告模式（Report）中按业务、租户、模型和服务器统计的 token。

**指标定义**：每千瓦时 token 数 = token 产出量 ÷ 服务器（或机柜，含其分摊的设施能耗）消耗的电能。该指标将 AI 机房的产出与电费直接关联，可按服务器、机柜或租户计算。能耗一侧为模型估算而非计量值时，标注为**估算**。

**故障推演**：每个场景均报告 **token 损失**。令一路供电故障、停止一台制冷单元或模拟一处漏液，Token 图层即显示随之损失的服务能力。

**当前数据来源**：演示机房内置 token 计数，您也可以通过 Readings 工作表（监测数据表）导入 token 与功率历史数据。来自推理服务栈指标与 GPU 遥测的**实时数据**经采集代理（Agent）的采集器接入；采集器已开发完成，尚未在实际运行的系统上测试（路线图）。

在多数 AI 机房中，每千瓦时 token 数仍依靠表格人工计算：功率取自一个仪表盘，token 取自另一个。将两者汇聚到同一机柜后，两台服务器、两个机柜或两个租户之间的对比直接以颜色呈现。可使用[每千瓦时 token 数计算器](/resources/calculators/tokens-per-kwh/)，或阅读[每千瓦时 token 数：AI 机房的核心指标](/resources/guides/tokens-per-kwh/)。

## 成本分摊与容量

报告模式并列呈现按业务、租户、模型和服务器统计的 token、按您的电价计算的能耗与成本，以及每千瓦时 token 数，成本分摊因此直接形成报告，无需另行制表。估算值均有标注。
